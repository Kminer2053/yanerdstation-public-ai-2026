# 범용 편집기 / 서울역 심사본 분리

이번 릴리스는 이전 `feedback-local-validation-2026-09-18.md`의 대전역 전용 제한을 변경한다.

## 공개 구성

- 소개: yanerdstation.kr — 서비스 Sites 프로젝트의 `/`
- 서울역: seoul.yanerdstation.kr — 같은 서비스 프로젝트의 `/seoul/`로 분기
- 편집기: toolkit.yanerdstation.kr — 별도 Sites 프로젝트, 별도 D1/R2
- 도메인은 DNS 소유 확인과 인증서 발급이 완료되어야 연결된다. 기본 Sites 주소는 별도로 유지한다.

## 서울역 데이터와 안전장치

- revision 334의 확정 등록부, 활성·비활성 시설, 8개 출도착 영역, 원점 53개, 일별 원점 자료 1,488건, 시간별 자료, 84개 층간연결, 28개 양방향 경로, 승인 파사드 94건 및 21개 현장 변경 구성을 불러온다.
- 지도는 최신화된 서울역 렌더러를 재사용한다. 따라서 기존 파사드와 추가·이동·철거가 동일하게 표시된다.
- 추가 포인트와 경로 변경은 편집 탭의 임시 레이어이다. JSON 내보내기는 허용한다.
- 서울역 저장·공개 설정·사진 업로드는 서버에서도 423으로 차단한다. 원본 Supabase 쓰기 권한을 편집기에 부여하지 않는다.
- 현장 모델 구성 JSON은 전체 열람·임시 수정할 수 있으나, 그 JSON을 변경했다고 원본 메시를 실시간 재구축하지는 않는다. 파사드는 미리보기와 데이터 구조를 확인할 수 있다.
- 지도 bridge는 고정 허용 origin + parent window를 검사하고 저장 작업을 제공하지 않는다.

## 범용성 / 준비 상태

역 ID, 이름, 기준 좌표, 층 목록·고도, 시작 층을 descriptor로 분리했다. 서울·대전 전용으로 고정한 좌표 검증과 층 UI를 제거했다. 같은 스키마로 다른 제공 역을 연결할 수 있다.

40개 역 전체의 공식 이름·ID·층 목록은 현재 원본 서버에서 검증하지 못했다. 서울·대전만 연결 확인 상태이며 나머지는 준비 중으로 명시한다. 38개 역의 이름·ID를 추정 등록하거나 원본 모델을 일괄 복제하지 않는다. 따라서 40개 역 전체 지도 검증이 끝났다는 뜻은 아니다. 저장공간 유료 증설은 하지 않았다.

## 소스 동기화 규칙

1. 공개 편집기에서 테스트·빌드하고 커밋한다.
2. `node tools/sync-toolkit.mjs`로 그 커밋의 추적 소스만 private `digitaltwin-station/toolkit`에 반영한다.
3. 서비스 테스트·빌드 후 서비스 저장소를 커밋한다.
4. 공개 편집기 GitHub와 private digitaltwin-station GitHub 양쪽에 푸시한다.
5. 각 Sites 소스와 동일한 빌드를 배포한다.

이 스크립트는 자동 GitHub 동기화 봇이 아니다. 향후 릴리스에서도 이 절차를 실행해야 한다. 별도 장기 토큰·GitHub Actions 권한을 만들지 않았다.

## 검증

- 기존 서비스 API/권한·데이터 합계·경로·카메라 수명주기, 상권 지표·시점, 지도 프록시 테스트 통과.
- 편집기 소유자 격리, 저장 충돌, 업로드, 범용 스키마, 서울역 서버 잠금 테스트.
- 전체 서울역 snapshot 변환 후 참조 유효성, N:N 승강기, 계단 중간 경유점, 원본 불변 검증.
- 실제 카메라 승인·현장 측위, 미확인 역 38개의 지도 연결, DNS 활성화는 각각 별도 확인 대상이다.
