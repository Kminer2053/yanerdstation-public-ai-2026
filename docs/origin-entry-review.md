# 원점별 진입 후보 적용 (2026-09-16)

사용자가 승인한 `entry-hourly-estimation-review.md`의 실행 범위.

- 48개 통계 원점과 물리적 진입 후보를 별도 ID로 유지한다. 여러 원점이 공유하는 후보는 지도에 한 번 표시한다.
- 기존 `/routes/?view=points`에 원점별 목록을 추가한다. 실제 출입문·개찰·연결부 후보를 누르면 해당 층으로 이동한다. 지도·파사드·격자 원본은 변경하지 않는다.
- 미확인 GTX·경의선 접속부, 주차장 보행출구, 외부 보행 동선은 미확인으로 표시한다. 대표 좌표를 보행 문턱으로 만들지 않는다.
- 기존 시간별 28원점 자료의 출처·분류를 유지한다. GTX·주차 20원점은 결측으로 표시하며 근거 확보 전 새 수치를 확정하지 않는다.
- 모든 출발·도착 후보는 미검수다. 가중치=null, route/routing/demand allocation=false. 후보 우선순위는 검토 순서이지 통행확률이 아니다.

## 실행 및 확인

1. `tools/test_origin_entry_review.mjs`: 데이터 커버리지·결측·중복·승인 잠금·검색/지도 변환 테스트를 먼저 작성하고 실패를 확인한다.
2. `tools/build_origin_entry_review.mjs`: 원본 pool.json과 현재 register.json에서 48원점과 수동 검토 정책을 결합해 `public/data/route-review/origin-entries.json`을 생성한다. 원본 파일 해시를 기록한다.
3. `src/origin-entry-core.js`: 후보 표시·검색·목록 HTML을 독립적으로 처리. `src/point-review.js`에 목록 전환과 지도 선택만 연결한다.
4. 기존 2개 테스트, 신규 테스트, 빌드와 데스크톱/모바일 브라우저 검증을 수행한다. unknown 좌표 생성 금지·원점 수와 물리적 후보 수 구분을 확인한다.
5. 연구 메모의 GTX·주차 근거를 기록하고 결측을 0으로 바꾸지 않는다. 소스 상태를 저장·배포하고 배포 상태 응답을 확인한다.

## 추가 근거 및 검증 한계

- 서울시설공단 시간별 주차현황 공개 목록(https://www.data.go.kr/data/15090908/fileData.do)을 확인했다. 2026-06-30 기준 파일이며, CSV 본문·7월 포함 여부·서울역 인근 19곳과의 대응은 미검증이다. 입출차 실적과 차량당 인원·역사 방문 비율은 별도 입력이다.
- GTX 역별 총량은 동일 기간·승차/하차 정의가 확인된 기준량을 확보하지 못했다. 과거 노선 전체 수치와 서울역 비중을 바로 곱해 확정하지 않았다.
- 로컬 Chrome에서 VWorld 원본 서버 연결이 시간 초과되어 실내 3D 장면의 시각 검증은 완료하지 못했다. 기존 지도/파사드 소스는 변경하지 않았다. 브라우저 테스트의 `--bridge-fixture`는 명시적인 지도 메시지 계약 테스트이며 실제 지도가 검증되었다는 뜻이 아니다.

## 데이터 판정 정책

외부 버스/주차는 동·서측 후보를 원점별로 명시한다. 실제 길을 검증하지 않았으므로 직선거리 최단경로·횡단 가능 여부를 주장하지 않는다. 주차장의 연결은 '역사 출입문 후보'이며 주차장 자체의 보행출구는 null로 유지한다.

한 개의 원점에서 여러 후보로 갈 수 있다. 원점 총량을 각 후보에 복제하지 않는다. 지하철 및 공항철도 개찰과 환승통로도 별도 경계로 보존하고 모든 유동인구를 2F로 올리지 않는다.
