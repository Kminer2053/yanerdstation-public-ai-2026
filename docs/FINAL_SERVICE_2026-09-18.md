# 서울역 이용 목적별 서비스

## 화면과 데이터

- `/`: 고객 검색/상품/가격/운영시간/위치와 보행 미리보기.
- `/?role=business`: 시간대별 진입·이동, 최대 3개 매장 이용 패턴/면적/인근 한 구간 통과량 비교, 직접 입력하는 손익분기 가정.
- `/?role=manager`: 위 분석과 승인된 계정의 일자·시간별 가공 매출, 면적당 비교, 운영 메모, 기존 시설·경로·원점·파사드 작업대.
- 세 화면의 목적 선택은 권한 부여가 아니다. 매출/메모/작업판 API는 SIWC의 per-site 사용자 ID 서버 허용목록으로 검증한다. 이메일은 화면 표시용이다.

2026년 7월 자료와 사용자 검토 작업판 리비전 334를 사용한다. 8개 출도착점, 56개 방향 경로, 활성 시설 115개, 승인 매장 29개와 인기상품 131개. 보행 출입점이 있는 62개 시설에 대해 출도착점 8곳으로부터 총 496개 경로를 생성했다. 출입점 미지정 시설에는 위치만 안내한다.

이용인원은 **결제건수 기준 가공값**이다. 고유 방문자 수가 아니다. 매출/이용인원의 원본 및 복원 키는 클라이언트에 넣지 않는다. 일별 합계와 시간대 합계가 일치한다. 시간대 값은 월별 구성비 적용 추정이며 영업시간 밖 실제 매출 구성비를 제거하지 않는다. 미확보 일자는 0으로 대체하지 않는다. 매칭이 승인되지 않은 영업자료는 제외한다.

GTX, 주차장, 원점 참여율, 시간확장 OD 배분의 확정 기준은 `/data/experience/methodology.json` 및 화면의 자료·추정 기준에 있다. 48개 외부 원점을 지도 밖에 그리지 않고 역사 내 진입점/검토 경로만 표시한다. 지도 통과량은 시간당 이벤트이며 면적당 실측 밀도·매장 방문자 수가 아니다. 7월 전체 공통 척도로 시간대가 바뀌어도 색/두께 의미를 유지한다.

## 공간 경험

`app/experience-scene.js`는 기존 VWorld 지도와 시설 현재화 모듈 위에 별도 레이어를 더한다. 다층 조망 시 구조물은 반투명으로, 경로는 화살표/점/안개로 표시한다. 따라 걷기는 눈높이 1.65m, 기본 1.2m/s와 진행률 조절을 제공한다. 자유 탐색은 검증된 보행 격자 간 연결 안에서만 이동하며 등록된 층간 연결을 이용한다. 원본 3D 모델의 재배포 권한을 가정하지 않으므로 VWorld 원본 캐시는 배포하지 않는다.

사람 모델은 기존 프로젝트의 CC0 에셋이다. 전체 기간 최대 시간대 대비 제곱근 비례 축소하여 데스크톱 최대 60명/모바일 20명으로 표현한다. 실제 사람 위치·인원·신원과 무관하다. 실내 조명과 야외 낮/노을/밤 배경은 선택한 환경과 시간에 따라 바뀐다. 실내/외 경계가 아직 검토 데이터로 지정되지 않아 환경 전환은 수동이다.

카메라는 사용자가 직접 켜고 허용해야 한다. HTTPS/localhost 지원 브라우저에서 후면 카메라를 우선 요청하되 마이크는 요청하지 않는다. 녹화·업로드·위치 추적·자동 AR 정렬은 없다. 닫기/숨김/페이지 이탈/권한 대기 중 취소 시 트랙을 해제한다. QA는 실제 카메라를 켜지 않고 모의 장치로 수명주기를 검사했다.

## 저장과 보안 운영

- 새 관리 데이터는 D1 `workbench`, `audit`, `facility_notes`에 보관한다. 낙관적 리비전 검사를 사용하며 충돌을 덮어쓰지 않는다. 입력은 공통 `validateWorkbench`로 서버에서도 검증한다.
- 원본 독립 작업판의 파일과 리비전 334는 수정하지 않았다. 새 서비스에서 저장한 내용은 별도 D1에 기록된다.
- 위치·경로 수정 시 유동배분/보행 그래프는 자동 확정하지 않는다. 기존 분석 리비전과 달라졌다는 표시 후 검토·재생성이 필요하다.
- `MANAGER_USER_IDS`는 Sites 런타임 환경변수의 명시적 per-site ID 허용목록이다. 누락 시 모든 관리 접근을 닫는다. 로컬에서는 Sites 서명 세션의 `local_seedy`만 허용한다.
- 기존 파사드 작업대는 **별도 Supabase 협업 서비스**를 유지한다. Sites 페이지 입구는 관리자 전용이지만 Supabase에 예전부터 설정된 공개 익명 편집 정책까지 바뀐 것은 아니다. 이 레거시 정책의 폐쇄/계정 이관은 Supabase 관리 권한으로 별도 적용해야 한다. 새 매출·메모·작업판 데이터는 그 서비스에 전송하지 않는다.
- 실제 개찰 통제, 에스컬레이터 운행 방향, 엘리베이터 대기, 휠체어 전용 접근성, 실내 측위는 현장 검증 전이다. 현재 경로는 **검토용 미리보기**이며 확정된 안전/무장애 경로로 광고하지 않는다.

## 검증

### 2026-09-18 화면 개편·연결 진단

- 운영 화면에서 Cesium 구동 이후 VWorld `metadata` 30초 시간 초과를 재현했다. DNS는 `1.224.180.151`을 반환했으나 원본 CDN의 TCP 443 연결은 6초/10초 검사 모두 실패했다. 원점·격자 데이터 렌더링 이전 단계의 실패이며, 이를 고치기 위해 등록 데이터를 삭제하지 않았다.
- 사용자가 Ubigi 해외 유심 테더링을 사용 중이라고 알려왔다. 해외망 경로/접속 정책 영향은 유력한 가설이나 국내망 비교 검증 전이므로 확정하지 않는다. 원본 직접 연결을 우선하고 실패하면 고정된 VWorld 경로만 허용하는 읽기 전용 서버 전달을 시도한다. 이 경로도 원본 연결이 막히면 실패할 수 있다. 캐시 저장·원본 모델 재배포·인증정보 전달은 하지 않는다.
- 원본 연결 실패 시 사용자가 별도 선택하는 간략 경로도를 추가했다. 등록 보행 좌표와 시설·경로만 표시하며 건축 모델/사진 파사드가 없다는 상태를 항상 구분한다.
- 소비자 지도 버튼을 전체/위에서/비스듬히/이동/회전/확대·축소로 교체했다. 시간 변경 시 `showFloors`가 동일한 층을 다시 설정해 카메라를 초기화하던 결함을 수정했다. 기존 카탈로그의 전문 편집 조작은 유지했다.
- 입점·상권 화면은 10개 기본 구역, 선택 매장 주변 반경, 구역 조망, 기기별 시점 저장·복원, 공간 지표와 비교표로 구성한다. 구역은 비교용이며 임대 경계가 아니다. 이용/매출 막대 척도는 지표별 7월 최대를 기준으로 고정한다. 한 이동의 인접 경로 구간들을 더해 중복 계상하지 않는다. 미매칭 영업자료·미확보 일자를 0으로 만들지 않는다. 좁은 화면에서 일부 상세 라벨은 생략하고 번호·목록을 유지한다.
- 시설·운영은 총괄(다층 지도, 매장 실적, 규칙 기반 확인 메시지), 시설(정보/파사드), 경로(경유점/층간 연결/출도착 영역/격자), 데이터(원점/시설)로 분리했다. 작업판 변경은 저장 확인 후 진행한다. 매출과 편집 API의 기존 승인 계정 제한을 유지한다.
- `node tools/test-spatial-workspaces.mjs`는 서버 전달 허용 경로/인증정보 분리/실패 처리, 동일 층 구역 판정, 경로별 1회 집계, PC·모바일 라벨 배치를 검사한다. 브라우저에서 로컬 실제 모델, 상권 구역·시점 버튼·저장, 관리 탭과 등록부, 모바일 가로 넘침을 확인했다. 실제 데이터 저장·카메라 촬영은 QA에서 실행하지 않았다.

`npm run test:experience`: 승인 매칭, 31일 일/시간 합계, 552개 경로 연속 좌표, 보행 그래프, API 인증/권한/CSRF/저장 충돌/감사 이력/메모, 모의 카메라 해제 검증. 테스트는 임시 메모리 DB만 사용한다.

`tools/build-experience-data.mjs`는 확정 산출물로부터 배포용 파생 데이터를 생성한다. `--graph`는 원본 로컬 캐시의 바닥/장애물을 검사해 경로를 재생성한다. 원본 Excel·CSV·시설 수정을 덮어쓰지 않는다. 사진 파사드와 기존 철거/추가/이동 내역의 회귀 검사를 병행한다.
