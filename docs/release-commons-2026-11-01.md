# 서울역 COMMONS · 2·3층 경량 탐색과 공유방

`/commons/`는 서울역 2층과 3층의 등록 공간을 별도 Three.js 장면으로 재구성한 경량 체험이다. 기존 정밀 서울역 서비스의 자유탐색 메뉴에서 들어가거나 이 경로를 직접 열 수 있다. 안내·상권·운영관리·공개편집기의 기존 기능과 저장 경로는 유지한다.

## 포함 범위

| 항목 | 현재 구성 |
|---|---|
| 보행 격자 | 2층 3,137개 + 3층 625개 = 3,762개 |
| 승인 파사드 | 리비전 337의 2·3층 59면 전수: 2층 51면 + 3층 8면 |
| 시설 등록부 | 2층 54곳 + 3층 7곳 = 61곳 |
| 현재화 구조물 | 기존 앱 모듈에서 가져온 custom 자산 12개 |
| 층간 등록 연결 | 에스컬레이터 7개 + 계단 3개 = 10개; 단방향 6개·양방향 4개 |
| 원점 | 기존 ENU 원점과 `east0=-4`, `north0=60`, `up0=8.98928` 유지 |

custom 12개에는 안내시설·매장 부스·사진부스·개구부 난간 등이 포함된다. 기존 시설 ID와 대응되는 자산은 같은 시설 정보로 연결하므로 **61곳과 12개를 더해 고유 시설 73곳으로 해석하지 않는다.** 별도 정보가 없는 자산에는 영업시간·상품·실적을 만들어 넣지 않는다.

등록된 2·3층 GRID와 승인 파사드 59면을 모두 포함하며, 형상 미확보와 범위 밖 제외는 각각 0건이다. 명시 배치 35건, 원본 연결면 복구 23건, 확정된 슬롯 치수 배치 1건으로 구성한다. 복구한 23건은 원본의 연결면 분리·UV 병합 규칙과 UV 서명, 예상 삼각형 수를 모두 대조한다.

2026-11-01 확인한 공개 승인 추가 자산·오버레이 목록은 비어 있다. 제보 초안에만 있는 ‘AI 역무원’ 키오스크는 최종 승인된 공개 형상이 없어 포함하지 않는다. 새 제보가 이 체험 기준본에 자동 반영되는 구조도 아니다.

## 구조와 화질

- 원본 3D Tiles를 실행 중 내려받지 않는다. 브이월드 관측 캐시의 실제 기둥·벽·계단·바닥·3층 외곽·창호·지붕 구조를 층별 경량 메시와 atlas로 가공한다. 기존 숨김·부분 철거 규칙을 적용하고, 보이지 않은 면을 사진만으로 만들어 내지 않는다.
- 현재 건축 파생 자산은 약 13.2만 삼각형, 16개 층별 메시 그룹이다. 4층·RF 구조는 2·3층에서 보이는 지붕 등의 배경으로 사용하며, 4층을 이동 가능 층으로 추가한 것은 아니다.
- 원본 마감 233종을 공통 2048² atlas에 담고 가까운 면의 상세 이미지를 별도로 불러온다. 여러 반복 셀을 가로지르는 UV는 정점별로 억지로 접지 않고 원본 평균색으로 대체한다. 넓은 바닥 반복면은 경량 타일 패턴을 사용한다.
- 승인 파사드 59면의 근접 이미지는 각각 최대 1536×1024, 원본 마감 상세본은 최대 1024 이내로 제한한다. 원본 URL과 실제 면 UV는 보존한다. 멀리서는 공통 atlas를 사용한다.
- 상세 사진은 처음에 모두 받지 않는다. 사진 계열은 모바일 3개·PC 5개, 원본 마감은 모바일 3개·PC 6개까지 가까운 대상을 선택하고, 멀어지면 GPU 자원을 해제한다. 승인 파사드 상세본 59개 합계는 약 1.96MB이며 custom 자산에도 별도 파생 사진이 있다.
- 플랫폼111은 기존 위치·높이와 KTX/문구 교대 시연을 재사용한다. 열차안내는 촬영 자료를 보정한 정지 화면으로 실시간 열차 정보가 아니다.

이 범위는 실내지도의 등록 자료를 바탕으로 한 체험이며, 서울역 전 공간의 현장 실측이나 현재 공사·운행 상태를 보증하지 않는다. 실제 이용 안내와 다른 층의 안내는 정밀 서울역 서비스에서 확인한다.

## 이동과 조작

- **층 선택:** 2층·3층 버튼을 누르면 해당 층의 유효한 시작 보행점으로 이동한다. 2층 기본 시작점은 `[10, 0, 20]`, 3층은 `[0, 6.116, 0]`이다. 같은 X/Z에 있는 2·3층의 높이와 충돌 경계를 분리한다.
- **시설 선택:** 목록에 층을 표기하고 전체·2층·3층으로 고른다. 시설 정보에서 가까운 유효 보행 지점으로 이동하거나 현재 위치에서 경로를 표시한다. 등록 정보가 없는 항목을 가짜 시설 정보로 채우지 않는다.
- **조망 위치 선택:** 조망 화면의 보행 지점을 누르고 확인하면 그 지점에서 산책을 시작한다. 공유방에서도 서버가 등록 `pointId`, 해당 층·좌표, 구조물 충돌 여부를 검증한 뒤 이동한다.
- **층간 이동:** 연결점 1.8m 이내의 실제 보행 가능 위치에서 모바일 이동 버튼이나 Enter를 누른다. 허용된 방향의 등록 경로로 이동하며, 이동 중에는 조작을 잠근다. 2.5~9초로 조정한 시연 이동 시간은 실제 보행·에스컬레이터 소요시간이 아니다.
- **기본 조작:** PC는 WASD 이동, 좌우 방향키 회전, 드래그 시점, 휠 거리, Space 점프, 1~4 인사·고개인사·만세·앉기다. 모바일은 왼쪽 조이스틱과 오른쪽 드래그를 사용하며 이동·시점·점프를 함께 입력할 수 있다.

조망·주광/노을·시설 목록·선택적 모의 산책자·성능 표시도 제공한다. 실제 접속자는 ‘여행자’, 가상 인물은 ‘모의 산책자’로 구분하며 가상 인물을 유동인구 통계로 표현하지 않는다.

### 등록 연결과 통행이 이어지지 않는 구역

10개 연결은 기존 compiled walk graph에 등록된 정보를 사용한다. 원본 `sourceStatus: draft`를 보존하고 화면에는 **‘등록 연결’**로 표시한다. 이번 작업을 통해 현장 검수나 최종 승인이 새로 완료된 것으로 해석하지 않는다. 등록 엘리베이터의 N:N 정차 구조를 처리할 수 있지만, 현재 자료에는 2층과 3층을 함께 잇는 엘리베이터 정차 그룹이 없어 임의 연결을 만들지 않는다.

같은 층의 보행 그래프는 2층 57개, 3층 13개 영역으로 나뉘며 가장 큰 영역은 각각 2,599개·518개 보행점이다. 원본 GRID는 전수 포함했다. 별도의 미포함 일반 경유점은 없고, 계단·에스컬레이터 디딤판은 등록 연결의 실제 경로에 보존한다. 벽·난간·지형 검사에서 통과하지 않은 구간을 새 통로로 잇지 않는다. 경로가 이어지지 않으면 층·시설·조망의 **위치 선택 이동**으로 접근하며, 이를 연속 보행 경로로 표시하지 않는다.

시설 앞 접근과 매장 내부 출입은 구분한다. 예를 들어 TRAIN MATES의 열린 문과 내부를 구조물 전체 박스로 막지는 않지만, 현재 기준본에는 해당 실내의 보행 격자가 없어 내부 진입은 지원하지 않는다. 미등록 실내를 임의의 보행 영역으로 확장하지 않는다.

## 공유방과 동기화

기존 Sites Worker와 D1을 사용하는 소규모 시험 운영이다. 별도의 웹소켓 서비스나 대규모 동시접속 기반을 새로 계약하지 않았다.

- 명시적으로 입장한 경우에만 약 1.2초 주기로 HTTP 동기화한다. 혼자 둘러보기는 공유방 DB를 사용하지 않는다.
- 방당 20명, 활성 방 5개, 전체 100명, 신규 방 30개/24시간, 방 생성 최소 5초 간격이다. 방은 생성 20분 후 고정 종료하고 20초 무응답 접속자는 만료한다. 백그라운드에서는 동기화를 멈추고 만료 후 재입장한다.
- 참가 토큰은 탭 메모리에만 보관하고 서버에는 SHA-256 해시만 저장한다. 공개 상태는 가상공간의 층·좌표·방향·동작·색상·임의 ID와 진행 중인 등록 이동이다. 실제 GPS·카메라·마이크·영업정보·로그인 식별자를 공유하지 않는다.
- 서버에서도 순번·동시 요청·재전송·최대 이동거리·출발 층의 경유 경로·층별 구조물 충돌 경계를 검증한다. 기존 지도·감사·관리 테이블과 분리된 presence 테이블만 갱신한다.
- `sync`에는 `floor`가 필수다. 보행 흔적 `path`는 출발 층의 `[x,z]` 배열이며, 지점 이동은 `move:{kind:'node',id:pointId}`, 층간 이동은 `move:{kind:'connection',id:connectionId}`로 요청한다. 높이 `y`는 서버가 해당 층에서 계산한다.
- 클라이언트는 출발 층의 일반 동기화와 미확인 경로의 ACK를 마친 후 이동을 요청한다. 응답을 잃으면 같은 순번·본문으로 재시도하고, 성공 위치와 층을 확인하기 전 임의로 도착 상태를 확정하지 않는다. 논리적 도착점과 화면상의 경로 이동을 분리하며 일반 heartbeat가 이동 애니메이션을 다시 시작하지 않는다.
- `commons_players`의 `floor`, `transit`, `moved_at` 필드를 사용하는 추가 마이그레이션이 필요하다. 방의 공간 버전은 `hall:architecture:custom` 조합으로 비교한다.

예를 들어 20명이 20분 계속 접속하면 동기화 요청은 약 20,000회다. 각 요청은 DB 조회·갱신·참가자 목록 조회를 포함한다. 사용량은 무료 무제한이 아니며 방 수 제한이 과금 상한을 보장하지 않는다. `COMMONS_DISABLED=true`는 공유방 API만 중지하고 혼자 보기와 기존 서비스는 유지한다. 만료 데이터는 다음 입장 정리 요청 때 presence 테이블에서 제거한다.

## 검증과 재생성

`npm run test:commons`는 전체 2·3층 보행점·층별 높이·동일 층 경로·등록 연결과 방향·지점 이동 검증, 승인 파사드 전수 대응과 UV·상세 이미지 예산, 구조물 충돌·우회, 토큰·순번·재전송·정원·만료·기존 업무 테이블 보존을 검사한다. 클라이언트는 DOM 참조·번들 검사와 출발 경로 ACK, 응답 유실 재시도, 429 대기, 422 위치 복구, 이동 중 heartbeat의 별도 검증도 수행한다.

`npm run preview:commons`는 `http://127.0.0.1:4210/commons/`에서 메모리 SQLite를 사용하는 격리 미리보기다. 기존·외부 API를 연결하지 않으며 종료하면 시험 접속 정보도 사라진다. `tools/check-commons-live.mjs`는 UI 방에 별도 시험 접속자를 잠시 연결하고 이동·인사 후 퇴장하는 검증 도구다.

`npm run build`는 hall·현재화 구조물·플랫폼111 파생 자산을 재생성하고 Vite로 기존 서비스와 함께 빌드한다. 복구된 원본 연결면 캐시를 저장소에서 추적하므로 일반 배포 빌드에는 원본 관측 캐시가 필요하지 않다. 건축 자산의 재추출은 별도 단계다.

1. `node tools/build-commons.mjs`: 전체 2·3층 보행·시설·승인 파사드 manifest와 상세 사진.
2. `node tools/build-commons-architecture.mjs`: 기존 로컬 관측 캐시에서 층별 건축 형상·마감·충돌 경계 추출.
3. `node tools/build-commons-custom.mjs`: 기존 현재화 모듈의 구조물·사진·출입점 대응.
4. `node tools/build-commons-screens.mjs`: 플랫폼111 시연 이미지.
5. `hallVersion`과 원점의 일치 확인 후 테스트·배포. 생성 자산도 저장소에 포함한다.

브라우저 성능 표시는 실제 렌더 횟수/초와 화면 루프 Hz를 구분한다. 정지 중에는 렌더를 생략한다. 기기·화면 크기가 다른 결과를 기존 서비스 대비 FPS 향상률로 주장하지 않는다. 모바일 에뮬레이션은 실제 휴대전화 성능 보증이 아니다.
