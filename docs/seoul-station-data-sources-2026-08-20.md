# 서울역 디지털트윈 데이터소스 조사

기준일: 2026-08-20  
범위: 서울역 내외 유동인구, 열차운행, 대중교통, 도로·주차, 혼잡도, CCTV, 날씨·행사·상권  
조사 원칙: 공공데이터포털을 포함한 정부·공공기관 공식 1차자료 우선

## 결론

서울역 **외부 생활권과 광역 교통상황**은 공개 데이터만으로도 상당히 실감 나게 구현할 수 있다. 가장 중요한 데이터는 서울시 실시간 도시데이터, 한국철도공사 열차운행정보, 서울 버스 도착·위치, 서울교통공사 역별 승하차, 도로 소통·돌발, UTIC 교통 CCTV, 기상정보다.

반면 공개 데이터만으로는 다음 항목을 얻기 어렵다.

- 서울역 층·매장·통로 단위 실시간 인원
- 특정 에스컬레이터나 출입구를 통과한 인원
- 매장별 체류시간과 방문 전환율
- 서울역 내부 CCTV 원영상
- CCTV·와이파이·BLE에 기반한 개인 또는 기기 단위 동선
- 매장별 실매출

따라서 시스템은 다음 세 계층을 구분해야 한다.

1. **공개 실시간 데이터**: 외부 혼잡, 열차·버스 운행, 도로, 날씨, 교통 CCTV
2. **공개 이력·통계 데이터**: 승하차, 상권인구, 월별 철도수요, 지하철 혼잡도
3. **내부 또는 모의 실내 데이터**: 층·구역별 인원, 동선, 매장 방문·매출

모의 데이터는 화면과 데이터에 반드시 `시뮬레이션` 또는 `모의`로 표시해야 한다.

## 3. CCTV 데이터의 현실적인 범위

### 공개 데이터로 가능한 것

- 서울역 주변 도로의 UTIC 교통 CCTV 영상을 지도 팝업으로 연결
- 공공 CCTV의 위치, 설치목적, 관리기관, 촬영방면 표시
- CCTV가 설치된 구역과 미설치 구역의 시설관리 현황 표현

### 별도 협의가 필요한 것

- 서울역 내부 CCTV 원영상 연동
- 원영상의 외부 전송·저장·재생
- 사람별 추적, 얼굴 또는 고유특징 인식
- 영상 기반 매장 방문자·체류시간 분석

내부 CCTV를 활용하더라도 대외 서비스에는 원영상보다 `구역별 현재 인원`, `혼잡등급`, `유입·유출 수` 같은 비식별 집계값만 내보내는 편이 적절하다. 관련 운영 기준은 [개인정보보호위원회 공공기관 고정형 영상정보처리기기 가이드라인](https://m.pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS290&mCode=D050050000&nttId=10480)을 기준으로 별도 검토해야 한다.

## 5. 내부에서 확보해야 할 데이터

### 공간 기준정보

- 역·운영주체·건물·층·구역의 고유 ID
- 매장 외곽 폴리곤, 출입구, 영업시간, 업종
- 개찰구·출입구·에스컬레이터·엘리베이터·계단 위치와 연결관계
- VWorld 실내지도 개체와 자체 개체를 연결하는 매핑표

### 유동·혼잡

- 출입구·개찰구·에스컬레이터별 1~5분 집계 통과 인원
- 층·구역별 현재 인원과 유입·유출 인원
- 센서 종류, 정확도, 결측 여부, 집계 기준
- CCTV 분석값을 쓴다면 원영상이 아닌 구역별 익명 집계 결과

### 매장·매출

- `매장ID, 일자, 시간대, 매출액, 거래건수, 객단가`
- `매장ID, 시간대, 방문자수, 입장자수, 체류시간`
- 휴점·행사·프로모션·재고부족 등 매출 영향 이벤트

### CCTV·보안

- 카메라 ID와 위치·방향·담당기관
- 원영상 접근권한, 보유기간, 외부제공 가능 여부
- 영상 분석의 법적 근거와 개인정보 영향평가 여부
- 대외 화면에 제공 가능한 집계 단위

## 6. 구현 순서

1. 서울 실시간 도시데이터에서 `서울역` 장소 호출을 시험하고 실제 응답 필드와 갱신주기를 확인한다.
2. 한국철도공사 열차운행정보로 서울역 도착·출발과 계획 대비 지연을 계산한다.
3. 서울역 주변 정류소 목록을 확정하고 버스 도착·위치를 연결한다.
4. 서울교통공사 승하차 데이터를 매일 저장해 자체 이력을 만든다.
5. 서울시 도로소통·돌발과 UTIC CCTV를 외부 접근성 레이어로 붙인다.
6. 기상·행사 데이터를 혼잡 원인 설명과 예측 변수로 결합한다.
7. 내부 층·구역·매장 ID 체계를 확정한 뒤 실내 센서 또는 명시적 모의 데이터를 연결한다.

## 7. 데이터 공통 필드 권고

모든 데이터를 같은 시계열·공간 체계로 합치려면 최소한 다음 필드가 필요하다.

```text
source_id            원천 데이터 ID
source_timestamp     원천이 의미하는 기준시각
ingested_at          우리 시스템이 수집한 시각
spatial_scope_type   장소/도로링크/역/층/구역/매장/시설
spatial_scope_id     내부 표준 공간 ID
operator             코레일/서울교통공사/서울시 등
floor_id             층 ID, 해당 없으면 null
zone_id              구역 ID, 해당 없으면 null
metric               population/board/alight/delay/congestion 등
value                값
unit                 명, %, 초, km/h 등
quality_status       정상/지연/결측/추정
is_synthetic         모의 데이터 여부
license_attribution  출처표시 문구
```

## 조사상 유의사항

- 공식 출처 27건을 조사했고, 23건은 새로 원문을 보존했으며 3건은 기존 보존본을 재사용했다.
- 서울시 실시간 도시데이터 매뉴얼 PDF 1건은 자동 수집기의 응답 크기 제한으로 보존하지 못했다. 데이터 설명 페이지와 다른 공식 원문은 확보했으므로 핵심 판단에는 영향이 없지만, 실제 개발 전에는 최신 매뉴얼을 직접 내려받아 요청·응답 필드를 다시 확인해야 한다.
- API 제공 페이지가 존재해도 키 발급, 호출량, 실제 응답, 서비스 종료 여부가 다를 수 있다. 개발 착수 전 P0 데이터는 모두 실제 키로 간단한 호출 시험을 해야 한다.
